## Steps (`run(cfg=None)` composed of step functions)
1. `p3 = read_artifact("p3")`, `p1` for the back-transform method. `level = cfg.p4.get("design_level", "target")`; spec = p3.target_complexity.design_spec (or the named ladder level's spec, rebuilt the same way p3 does: import that helper from src.phases.p3) + cfg.p4.candidate_blocks (skip a candidate whose columns are already present). `design_from = {level, index, n_features_before_candidates}`. Design fitted on train_df.
2. `unregularised`: ridge_closed_form(alpha=1e-8) → train/val r2, rmse.
3. grids: ridge = n_alphas log-spaced over ridge_alpha_range; lasso = alpha_max(ρ=1) × logspace(0, log10(l1_alpha_min_ratio), n_alphas); elastic net: same construction per ρ in l1_ratios.
4. validation curves: per method (and per ρ) the whole path on train → for each α `{alpha, val_r2, val_rmse, train_r2, n_nonzero}`. Chosen α (and ρ) = argmax val_r2; tie → larger α. Store curves under `curves.{l2, l1, enet.<rho>}`.
5. day-block CV inside train (folds from `day_block_folds`; a new Design is fitted on each fold's fit rows): ridge grid, lasso grid, elastic net at the chosen ρ only → per α mean and standard error of fold R² (bike scale). Store `cv.{method} = {alphas, mean, se, cv_best_alpha, cv_1se_alpha (largest α with mean ≥ best mean − its se), val_r2_at_cv_best, val_r2_at_cv_1se}`. Note the α grids for L1/ENet are the absolute values from step 3 (not rescaled per fold).
6. per method at its chosen hyper-parameters: `methods.{l1|l2|enet} = {lambda, l1_ratio (enet; 1.0 for l1, 0.0 for l2), val_r2, val_rmse, val_lo, val_hi (bootstrap_r2), train_r2, train_rmse, n_nonzero, n_features, day_block_r2, day_block_se, chrono_r2, chrono_rmse}` (chrono: Design + model fitted on the early part, scored on the late part, cut from cfg). Key names `l1`, `l2`, `enet` exactly.
7. `comparisons` = paired_bootstrap_delta_r2 on validation for l1−l2, enet−l2, enet−l1, and each method − unregularised: `{delta, lo, hi}`.
8. `recommended`: let best = max val_r2. Candidates = methods whose paired interval versus the best includes 0 (the best itself included). Recommended = the candidate with the highest day_block_r2. Store `{method, lambda, l1_ratio, val_r2, val_rmse, day_block_r2, chrono_r2, rule: "within-noise on validation, then best on held-out days", intercept, weights, feature_names}`.
9. coefficient paths for plots: `paths.{l1|l2} = {alphas, coef: {name: [...]}}` for names temp, atemp, hum, windspeed, workingday, holiday, trend, yr, instant, ws_3 (those present). Lasso `entry_alpha[name]` = largest α on the lasso grid with a non-zero coefficient (null if never) for every feature.
10. stability: `stability_selection` for lasso at its chosen α and for elastic net at its chosen (α, ρ), groups = training dates, seed = team seed, B and threshold from cfg → `stability.{l1|enet} = {freq: {name: f}}`.
11. `rich_check` (does a penalty rescue the over-fit top of the ladder?): the LAST ladder level's spec (no candidates): unregularised, ridge path and lasso path on validation → `{level, n_features, unregularised_val_r2, l2: {lambda, val_r2, day_block_r2}, l1: {lambda, val_r2, n_nonzero, day_block_r2}, paired_best_vs_recommended: {delta, lo, hi}}`. Informational only.
12. verdicts (`src/verdicts.py`, pure functions; ORIGINAL = season, yr, mnth, hr, holiday, weekday, workingday, weathersit, temp, atemp, hum, windspeed, dteday, instant). Reference model = ridge at its chosen λ on the full Phase 4 design; a "drop" removes columns from X_tr/X_va (no re-standardising) and refits ridge with the same λ.
    - `involving(c)` = features with c ∈ sources; `own(c)` = features with sources == {c}.
    - GROUPS: temperature = {temp, atemp}; season = {season, mnth, dteday}; level = {yr, instant, dteday}; daytype = {weekday, workingday, holiday}. `partners(c)` = union of the groups containing c, minus c (hr, weathersit, hum, windspeed have none).
    - numbers per column: `drop_alone = {delta, lo, hi}` (paired bootstrap, full − dropped, on validation) and `drop_alone_day_block` (mean fold Δ, Design refit per fold, same column removal); `drop_group = {delta, lo, hi, members}` removing involving(c) ∪ involving(p) for all partners (null when no partners); `solo_r2` = validation R² of ridge (same λ) on own(c) only; `lasso = {n_own, n_own_nonzero, n_involving, n_involving_nonzero, max_freq_own, mean_freq_involving, entry_rank}` (entry_rank = rank of the column by the largest entry_alpha among own features, 1 = enters first); `max_abs_corr = {value, with}` = largest |correlation| between an own feature of c and an own feature of another column (train); `vif_max` over own features, from the first-order standardised columns of the Phase 4 design (pinv-based, capped at 1e6).
    - rule (thresholds from cfg.p4.verdict): alone_hurts = drop_alone.lo > 0 and drop_alone.delta ≥ min_delta. group_hurts = drop_group.lo > 0 and drop_group.delta ≥ min_delta.
        useful: alone_hurts.
        redundant: not alone_hurts and (group_hurts or solo_r2 ≥ solo_min).
        uninformative: otherwise.
      Representative fix: inside each GROUP, if group_hurts for its members but no member is `useful`, promote the member with the highest solo_r2 to `useful` (set `representative: true`); it is the copy we keep. `carried_by` for a redundant column = the useful members among its partners (or, for a column without partners, the `with` of max_abs_corr).
    - `column_verdicts[c] = {verdict, evidence (one sentence built from the numbers, e.g. "dropping it alone changes validation R2 by +0.0002 [-0.0003, +0.0007]; dropping it with atemp costs 0.0213; lasso keeps 1 of 1 own columns in 62% of resamples; r = 0.985 with atemp"), carried_by, representative, numbers: {…all above…}}`.
13. survivors: `survivors_expanded` = features with lasso coefficient ≠ 0 at the chosen α AND stability.l1.freq ≥ threshold AND every source column has verdict "useful". `survivors_original` = columns with verdict useful and ≥ 1 surviving feature. `survivor_refit` = ridge (chosen λ) on the survivor columns only → `{n_features, val_r2, val_rmse, day_block_r2}`; `survivor_counts = {lasso_nonzero, stable, after_verdicts}`.
14. artifact `p4`, upstream "p3". chain_check keys verbatim: methods, survivors_original, survivors_expanded, column_verdicts. Plus design_from, design_spec, feature_names, n_features, unregularised, curves, cv, comparisons, recommended, paths, entry_alpha, stability, rich_check, survivor_refit, survivor_counts, not_converged, grids summary (min/max α per method).
