## 9 Over-claims and unbacked statements

1. Report §1: "selection ... fitted on the training rows only". The removal of 18 features is decided by validation drop tests and λ by validation R² (C2b).
2. "Survivors = what L1 leaves non-zero": Lasso removes 1 of 280 features (`survivor_counts` 280 → 279 → 279); all real pruning is the drop-test verdicts. Stated numerically in cell 75 and report §5, but the framing invites "your L1 selected nothing". Also the recommended enet has 272 non-zero weights while "279 survivors" are handed on.
3. Report §7: "for unseen future months the honest figure is the chronological 0.914". That split was used to accept C6 and to choose the survivor order, so it is also selected-on; it is one six-month window.
4. Bonus: the 1.28 upward shift is attributed to the 3:1 cost, but the comparison is log-scale MSE against a bike-scale asymmetric loss. Moving to the bike scale alone moves predictions up (the report itself says the log fit targets the median). There is no k = 1 control.
5. "Rule, fixed in advance" (cell 76) for the stage-B recommendation, in the same paragraph that says stage B was added after the first run. enet wins the tie-break by 0.00006 held-out-day R² against a fold standard error of 0.003; it is also the validation argmax, which is the cleaner justification.
6. `holiday` = redundant rests only on the group test (solo R² 0.000, drop alone 0.0000); the group cost 0.1879 is weekday/workingday's, and would label any junk column in that group redundant. The true evidence is the exact identity holiday = (weekday is Mon–Fri) and workingday = 0, which is not shown as a number.
7. Numbers with no artifact: reference-library agreement 1e-3; tree model 0.944; the notebook points to `exp/analyst/` and `exp/eda0/`, which are not part of the submission.

## 10 Live-defence risks

1. **The notebook contains no algorithm.** All 71 code cells call `src/` (4,674 lines) and print artifact fields; gradient descent, the lift, coordinate descent and the logistic fit are not visible in the .ipynb, and the .ipynb alone cannot run (needs `src/`, `config.yaml`, `data/`, `artifacts/`). The description asks for a notebook that "contains all five phases" and that every member can change on the spot.
2. **Changing any knob costs about 20 minutes.** `cached_or_run` reruns Phase 4 (15–20 min) and Phase 5 (3 min) whenever `CFG` differs from `config.yaml` or the upstream hash changes; a rerun also overwrites `artifacts/*.json` and `sample_submission.csv`, after which the report numbers no longer match until `git checkout -- artifacts sample_submission.csv`. On another machine a last-bit difference in p1.json would trigger the same cascade on a plain "Run all". Cell 0 promises "a few minutes".
3. **Code a student is unlikely to explain cold:** covariance-update coordinate descent (`cd_sweep`, q = Gw), ridge path by eigendecomposition, group-bootstrap stability selection, paired bootstrap, VIF through a pseudo-inverse, tie-aware Mann–Whitney AUC, Armijo backtracking, the dataclass/`replace` plumbing of `p4.py` (668 lines).
4. **Constants that need a sentence each:** `ETA_HEADROOM 1.0`, `EXP_CAP 20`, Armijo `1e-4` and "10 quiet iterations", divergence at `1e6 × L0`, `365.25`, `SOLVER_TOL 1e-7`, `NONZERO_TOL 1e-10`, `OVERFIT_MARGIN 0.002`, `AUC_TIE 1e-4`, `BOOTSTRAP_RNG_OFFSET 5`, stability 50 / 0.6, verdict 0.001 / 0.01, `PROFILE_BAND`.
5. **The history the notebook points to.** Five cells say "see the git history of this file". That history is a single afternoon, with agent-role commit messages and repository files such as a master prompt, a token ledger and `handoff/`. The description requires justifications "in your own words" and that every member can explain everything; the team should expect questions on how the work was produced and be ready to answer them openly.
6. Kernel is Python 3.14.3; confirm the evaluation machine can run it.

## 12 Judgment on the grading criteria

- **Accuracy:** strong for a linear model (validation R² 0.939, RMSE 45.5; held-out days 0.943).
- **Robustness on unseen days:** good evidence (train–validation gap 0.008, five day folds, chronological 0.914, test predictions sane and reproducible). The validation, day-fold and chronological figures are all mildly optimistic because each was used for decisions.
- **Chain integrity:** strong (hashes, exact loss hand-over, deterministic rerun).
- **Compliance:** no violation found; roster IDs unconfirmed; "selection on train only" sentence is wrong.

**Three weakest points an examiner would attack**
1. The notebook is a thin wrapper that cannot be changed and re-run on the spot, and the team must explain 4,700 lines it does not show.

3. Phase 4 selection: L1 removes one feature; pruning is done by validation drop tests while the report says selection is train-only; the chronological "honest" figure was itself used to choose.
